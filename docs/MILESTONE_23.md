## Interactive queue and recovery

`campaign_queue` accepts only the current checkpoint's listed line/reset input. The server stores an ordered permutation of the three party IDs, desk correction, line readiness, empty-bucket/chair state, reset readiness, bounded checks and feedback. Reordering cannot delete or duplicate parties. Arrival order alone cannot pass before the desk verifies the duplicate. Manual and guided ordering/reset both need an explicit check. An incorrect check retains progress and costs nothing; a ready phase ignores further moves/checks.

Revision/receipt transactions serialize controls; a repeated movement key/body returns the original swap, and completion cannot duplicate mastery. Wrong-stage/cross-phase controls, forged task objects and skipped checks are rejected. Pause/reload, save-code recovery and server restart retain partially ordered tickets and corrections. Journal navigation blocks queue input and never grants the transport note before chapter completion.

The existing distance-based actor renderer moves three original pedestrian roles between marked positions. Facing follows displacement consistently; served parties can leave the scene completely without looping back. Optional animation off preserves the essential ordered positions, ticket text and task cues. The bus uses an alpha-bounded tire baseline and parking shadow independent of viewport width. The aisle reset uses a code-native empty bucket/chairs; the later reservation has its own desk tableau. This is bounded authored staging, not general crowd collision, shared-world traffic or a fuel-dispensing simulation.
